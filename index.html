Summary

We will be building a pipeline that will convert a 3D model into a 3D Gaussian splat that can be viewed with lighting and textures in real-time. The main goal will be to take in an .obj file containing a 3D model and output a .ply file containing the 3D Gaussian splats which can be viewed in an external website such as SuperSplat.

Problem Description

What is 3D Gaussian Splatting?

3D Gaussian Splatting (a.k.a. 3DGS) is a rasterization technique typically used to turn small samples of images into photorealistic scenes that can be viewed and rendered real-time. The technique replaces triangles used in rasterization with Gaussian splats. These splats are in the shape of ellipses that can be stretched and scaled to form the shape of the scene. They store information such as position, covariance (stretch/scale matrix), color, and alpha (transparency). With millions of splats, they can form photorealistic scenes that are easy to render to the point where they can easily be viewed in a browser at websites such as SuperSplat.

The basics of the 3DGS pipeline includes:

  1. Structure from Motion (SfM)
    • From a set of 2D images, create a 3D point cloud estimating the scene
  2. Converting to Gaussians
    • Convert each point in the point cloud to a roughly estimated Gaussian splat (gsplat)
  3. Training
    • Rasterize and render the gsplats to obtain an image
    • Compare the image to the ground truth image (from the original set of images)
    • Use Stochastic Gradient Descent to minimize the difference (loss) by adjusting each gsplat's parameters
Other techniques such as Differentiable Gaussian Rasterization and Adaptive Density Control (densification) are also used to optimize the pipeline.

The Problem

3D Gaussian Splatting is mainly used for converting scenes in real-life, however it can also be used for already existing 3D models and more generally any 3D scene that we can take snapshots of. The main purpose for taking an existing 3D polygon model and converting it with 3DGS is to create a visualization of the model that does not require rendering it entirely. With 3DGS, you could view the model at all angles with proper lighting, shading, and texturing included as opposed to seeing the 3D model pre-render. An example of this can be seen here.

Implementing this will be tricky given that we are essentially reworking the first part of the 3DGS pipeline (Structure from Motion). Instead of taking high quality pictures and using those, we will instead need to produce reference images of the 3D object by rendering it at certain angles.

The initial idea we have in mind for achieving this is by setting up (or simulating) a multicamera setup that captures the model from many angles (think of a sphere of cameras surrounding the object) that will allow us to render out these reference images. Of course, rendering too many reference images would defeat the whole purpose of avoiding a lot of rendering as well, so we need to find an optimized way of achieving this.

Goals and Deliverables

Questions We Plan To Answer

  • How do we find the optimal coverage of reference images that best represents the 3D object while using minimal amounts of rendering?
  • Given that we are already working with a 3D representation of an object, does there exist any useful information that can help optimize the conversion to gsplats?
  • How do we ensure that properties such as textures, lighting, and shading are all preserved in the final 3DGS result?

Measurements

  • We will be measuring the time it takes for our program to take a 3D object file (.obj) and output the 3DGS file (.ply).
  • We will also be comparing the result of the .ply file to renders of the 3D object to check for accuracy.

Must Deliver

  • A pipeline that will take in a 3D object file (.obj) and produce a 3D Gaussian splat (.ply) in an optimal amount of time.

Hope To Deliver

  • Included optimizations such as Adaptive Density Control (densification) to further speed up the pipeline.
  • Adaptive camera placement for irregular / large 3D models
  • Support for changing the location or type of lights used

  • We will start from libraries rather than from existing project code. Everything between the pointmaps and the splats will be written by us.
  • We will be using SuperSplat to view our .ply files.
